# Settings secret traversal and consumer boundaries

The traversal is pinned to nightly 4288 (`32a0531748c44b25072d7495ce0b9bd7e9450a87`). `settings-secret-fields-4288.json` is generated from the actual provider, source-control, usage-source, EAS and Simlock schemas. An ordinary string credential field does not acquire reference support merely because another field in the same configuration supports it. GitHub `signIns`, for example, remains a string map; `tokens` supports references.

`settings_secrets` ports the native secret-slot naming, callback order, host-name normalization, reference-preserving value mapping, removed-provider cleanup and selective refresh collection. A global settings refresh collects source-control, usage-source and device references. Provider-instance references have their own instance-scoped refresh path. An unreadable settings document invalidates the complete resolver cache; a readable document containing no references invalidates none.

`materialize_profile` creates a read-only consumer snapshot from native private `.bin` slots. It does not update the stored settings cache, rewrite settings, migrate a credential store or implement the native persistence transaction. Missing private slots become empty literals. Actual references remain references until their configured resolver supplies a nonblank value. Private files are opened without following a final symlink and must be regular files.

GitHub star credentials now use this snapshot and the native host schema before existing account selection. A missing or blank saved literal permits the existing environment or CLI fallback. A valid reference that cannot be read refuses that fallback, including a previously cached account credential. A configured app session remains a separate account boundary; this change does not implement the native app-session renewal driver.

Usage-source refresh resolves the declared management key before contacting the hub. Missing literals and unreadable references retain their distinct native messages. Global provider refresh invalidates settings references and refreshes usage sources before refreshing providers. Instance-scoped refresh does neither. Usage-source refreshes share a per-server serialization lock and publish their snapshots to opted-in subscribers. The reset-credit route and strict hub API are implemented in [CLIPROXY-NATIVE.md](CLIPROXY-NATIVE.md). Full native usage-account projection and runtime-specific transport normalization remain separate unfinished work.

## Evidence

`tools/generate-settings-secret-fixtures.mjs` executes the complete native mapping and reference-resolution helper bodies against Effect 4.1.2 and the actual schema registries. Its fixture includes 134 traversal/removal/invalidation cases, 15 host-decoding cases, 28 schema-declared reference-resolution cases and eight literal/refusal cases. The managed settings codec generator also compiles the actual source-control host schemas and usage-source schema; it does not infer validation from default values.

Run source generators and test binaries only in rootless Podman with read-only source/runtime mounts, a private temporary directory and HOME, and networking disabled. Physical consumer tests copy synthetic `op` and `gh` executables into private fixture directories; they never mount real authentication stores or call an external service. Synthetic loopback HTTP captures the resolved credential at the consumer boundary. Fixtures do not link to host paths or recursively remove directory trees.
