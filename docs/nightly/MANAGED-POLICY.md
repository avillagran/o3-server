# Managed policy parity checkpoint

The reference is T3 Code nightly 20261106.4262 (`c55db3e9c72fdf584f4b54192fb39beb88667b59`). The 38 source files listed in `managed-policy-intake.json` are byte-identical through nightly 20261106.4275 (`6577c6b6185167c0e502fa01f9e8e8f2dee6ff25`). This verifies the recorded policy scope, not all nightly functionality.

Machine policy intake is immutable for the server lifetime and uses the native machine paths. A malformed policy or a requested policy family without complete consumers refuses startup with exit 77. User profiles and environment variables cannot replace the administrator policy. Linux file intake and macOS preference decoding are implemented; the Windows system loader remains unavailable.

Authentication and webhook restrictions are enabled. Webhook policy is checked before identifier lookup or logging, including imported deliveries and legacy queues. Policy does not erase deliveries or replay claims.

Provider controls now cover effective launch configuration, locked/default values, hidden stored environment values, driver availability, project enablement, and model-selection fallback. Configured Codex and Claude transports and setup/auth subprocesses remove inherited `T3CODE_CODEX_LAUNCH_ARGS` under any policy before applying explicitly configured instance variables. Runtime ceilings remove launch configuration and environment that could bypass the ceiling. Admission checks reject provider/runtime changes transactionally; recovered runs check frozen execution policy before acquiring a provider start claim.

`tools/generate-managed-provider-fixtures.mjs` executes the complete pinned native policy module and imported provider schemas using Effect 4.1.2. Its fixture contains 96 platform/policy/layout combinations and 768 write verdicts. An additional 266 cases execute the native text-generation fallback with driver allowlists, disabled instances, and custom model selections. Fixture regeneration is byte-identical. The Rust comparator checks every overlay, lock list, and write verdict. Physical container tests exercise both native transport protocols, policy-pinned executables/arguments/environment, preservation of stored user values, blocked discovery/polling, inherited launch overrides, and transactional/recovered-run rejection. Settings RPC errors preserve native managed-setting and disallowed-provider metadata. A separate official runtime RPC acceptance verifies effective pins, both rejection shapes, policy defaults, hidden stored values, legacy streaming migration, global and real-project runtime clamping, and sparse persistence without inference.

All test executables run in rootless Podman with read-only source/runtime mounts, a private home and temporary filesystem, and no network. The official RPC runner additionally mounts a private temporary `/etc/t3code`; it never writes the host machine policy and performs no inference.

Provider, runtime, settings, client, connect, telemetry, browser-cookie, and updater families remain behind the startup readiness gate until each complete consumer path and its acceptance checks are available. Provider leaf and transport tests alone do not enable an unfinished family.
