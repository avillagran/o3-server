# Managed client controls checkpoint

The implementation follows nightly 20261106.4262. The source scope and hashes in `managed-clients-intake.json` are unchanged through nightly 20261106.4288. This checkpoint does not enable the Clients or Connect readiness gates.

Server startup derives web versus remote authentication from the actual requested host. Reachability checks run before profile ownership and creation, and restricted local binds use the approved literal address. Before the real bind, Tailscale enforcement checks that the port is available, reads Serve configuration, removes only unambiguous machine-owned routes targeting this listener, and reads configuration again. It preserves unrelated routes. Tailscale Services, foreground owners, ambiguous targets, and former machine names prevent startup when they still forward here. A missing CLI or confirmed inactive daemon is distinct from an unreadable or unauthorized daemon. Commands have bounded time/output and process-group cleanup; errors never include raw stderr.

The complete pinned native Tailscale module generates 5,533 Serve parser cases, 49 status cases, and 36 selective removal argument cases. Five physical tests use a synthetic argv CLI inside a rootless container. Six client and bridge tests cover revocation, transport identity, pairing, and publication. An official runtime comparison verifies the same allow/refuse decisions, refusal messages, and command sequence for seven startup scenarios without inference.

Pairing uses the native `one-time-token` subject. Policies that forbid remote clients reject ordinary pairing creation. Only trusted transport metadata supplies the peer address; client labels, request bodies, and forwarded headers cannot turn a remote exchange into a local one. Startup bootstrap grants retain their local exception. Revocation affects native paired-link and Connect identities plus bootstrap sessions with recorded nonlocal peers; it preserves unrelated administrative sessions and local or unclassified bootstrap sessions. The official CLI/profile acceptance verifies persisted revocations and pairing decisions for local-only and Connect-disabled policies.

Embedded OmaBridge streams are classified as remote independently of their HTTP headers. A policy that forbids remote clients prevents bridge publication and credential minting, and the default embedded node stays off. Disabling T3 Connect alone does not disable an independent OmaBridge transport. Existing TCP forwarding performed by an independently owned external process is outside the embedded transport's identity boundary; this checkpoint does not modify or claim ownership of that process.

Desktop-managed authentication requires the real inherited bootstrap envelope and rotating token protocol. A desktop UI starting a headless service does not make that service a desktop-managed endpoint. No desktop bootstrap support is advertised here. T3 Connect also needs the actual CloudLink and endpoint-runtime ownership/stop lifecycle before owned secret cleanup can be implemented safely; deleting secret files alone is insufficient.

All executable acceptance runs use rootless Podman with private HOME/tmp, read-only source/runtime mounts, and no network. Official policy tests use a temporary container-only `/etc/t3code`. No live Tailscale, authentication, cloud credentials, or services are changed.
